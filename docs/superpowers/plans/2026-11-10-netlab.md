# netlab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Um JAR Java (`netlab`) com modo `server` (echo TCP/UDP) e modo `client` (prompt interativo que roda experimentos e serve um painel web em tempo real via SSE) para observar TCP vs UDP entre Mac e Windows, com o iPhone como visor.

**Architecture:** Pacotes sem rede (`wire`, `event`, `impair`, `metrics`) testáveis isoladamente; `server`, `experiment` e `dashboard` tocam sockets; `cli` liga tudo. Experimentos publicam eventos num `EventBus` não bloqueante; `MetricsAggregator` gera snapshots a cada 250 ms; `DashboardServer` transmite eventos filtrados por SSE.

**Tech Stack:** Java 21, Maven, JUnit 5, `java.net`, `com.sun.net.httpserver`, HTML/JS puro.

**Spec:** `docs/superpowers/specs/2026-11-10-netlab-design.md`

## Global Constraints

- Java 21 (`maven.compiler.release=21`); pacote base `dev.klleriston.netlab`; `groupId` `dev.klleriston`, `artifactId` `netlab`; JAR final `target/netlab.jar` com `Main-Class: dev.klleriston.netlab.cli.Main`.
- Zero dependências em runtime. Única dependência: `org.junit.jupiter:junit-jupiter:5.11.3` em escopo `test`. Plugins: `maven-surefire-plugin:3.5.2`, `maven-jar-plugin:3.4.2`.
- Portas padrão: TCP 7000, UDP 7001, HTTP 8080. Porta fechada do `lifecycle`: 7999.
- Tamanho máximo de mensagem: 64 KiB (65536 bytes). Payload padrão: 64 bytes.
- Timeouts: connect TCP 3 s; leitura TCP 5 s; perda UDP 1 s.
- Snapshot de métricas a cada 250 ms. Fila padrão por assinante do `EventBus`: 10 000. Limite SSE de `PacketLost`/`PacketReordered`: 50/s por conexão.
- Tempo injetável (`LongSupplier nanoClock`, padrão `System::nanoTime`); aleatoriedade injetável (`java.util.Random`).
- Textos voltados ao usuário (terminal, painel, README) em português.
- Um commit por tarefa (ou por passo de commit indicado), mensagens em Conventional Commits, terminando com a linha `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Testes de integração usam `127.0.0.1` e porta 0 (efêmera); nunca portas fixas.

## Review Focus

1. **Alta taxa no `throughput`** — milhares de `PacketSent`/`PacketEchoed` por segundo podem encher a fila do agregador; esperado: métricas não travam o experimento e o snapshot expõe `droppedEvents` em vez de mentir silenciosamente. Teste na Task 4.
2. **`stop` com experimento bloqueado em `read`/`receive`** — esperado: `ExperimentAborted` em até 1 s, sockets fechados. Teste na Task 6.
3. **Echo UDP que chega depois de declarado perdido** — esperado: conta como `PacketLate`, nunca como ecoado nem perda duplicada. Teste na Task 7.
4. **Servidor desligado ou IP errado** — esperado: `ExperimentFailed` com a dica de firewall, e o cliente aceita o próximo `run`. Teste na Task 6.
5. **iPhone desconecta e reconecta no meio de um experimento** — esperado: o experimento não bloqueia, o assinante é removido e a nova conexão recebe primeiro os últimos snapshots. Teste na Task 10.

- [ ] **Step 3: Implementar**

`decide`: ordem de sorteios fixa — (1) `random.nextInt(100) < lossPercent` → `Decision(true, 0)`; (2) `delay = delayMs + (jitterMs == 0 ? 0 : random.nextInt(2*jitterMs+1) - jitterMs)`, mínimo 0; (3) `random.nextInt(100) < reorderPercent` → `delay += 20 + 2*jitterMs` (segura o pacote para que os seguintes o ultrapassem).
Socket: o caminho de envio aplica `decide` e agenda o `delegate.send` de uma **cópia** dos bytes num `ScheduledExecutorService` de uma thread daemon (delay 0 envia direto). O caminho de recepção usa uma thread leitora daemon que lê do delegate, aplica `decide` (drop descarta) e agenda a entrega numa `LinkedBlockingQueue`; `receive()` faz `poll(timeout)`. Exceções do delegate (`PortUnreachableException`) entram na fila como marcador e são relançadas no `receive()`. `close()` fecha o delegate e encerra as threads.
